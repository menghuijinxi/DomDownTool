# 百度矢量 GIS 前端协议验证

这个独立原型用于核对百度原生分级格网、专用二进制、差分顶点、原始三角网格、
地点锚点和建筑挤出字段。桌面程序现已通过独立 C++ 解码和下载模块接入百度 GIS，
这个原型继续用于协议对照。已有百度卫星和电子栅格底图使用原有入口。

## 运行

在项目根目录执行：

```powershell
node tools/baidu-gis-prototype/server.mjs --port 8777
```

打开 `http://127.0.0.1:8777/`。默认加载北京的九个原生 z19 瓦片。
可以切换四个样区、输入 BD09 坐标、选择原生数据层级和加载范围、
筛选业务分类、几何类型与原始样式、显示原始要素属性、调节透明度和主动导出 GeoJSON。
地图缩放改变显示比例，不自动替换已下载的数据层级。

地图采用 BD09 经纬度与百度墨卡托投影，直接对照百度电子底图。
**这里导出的坐标为 BD09，不是 WGS84。** 顶层及要素均带有坐标系标记。
正式程序复用现有百度到 WGS84 的转换能力，输出 WGS84 外环和孔洞。

## 当前边界

- 根据官方 WebGL SDK 读取版本配置、原生数据层级、格网尺寸和请求参数编码。
  格网配置变化时服务明确报错，不继续套用旧规则。
- 二进制版本 2 的块目录、Int32 差分坐标和 Uint16 三角索引独立还原。
  面按原始三角网格绘制，不把所有顶点直接连接成未经验证的外环。
  GeoJSON 用 `GeometryCollection` 保留原始三角面；不声称已经恢复外环和洞。
- 几何支持建筑、地表面、叠加面、地表线、立体线及地点/文字锚点。
- 使用官方编辑器的 `getfeaturetype` 查询业务类型；本轮实测无需登录、Cookie 或 AK。
  已核对建筑、水体、绿地、道路、高速、铁路/高铁、地铁，以及景点、教育、
  医疗、地产小区、休闲娱乐、交通设施、其他人造区域和道路设施。
  图层按业务类型筛选，几何类型独立筛选；点锚点不混入水体面、建筑面或道路线。
  业务类型和原始几何组同时保留为 `featureType`、`geometryCategory`。
  v088 / 20261021 的原生 z19、组 15、编号 `504812/504813` 已结合官方绘制分组、
  默认样式和四城跨层级道路中心线对照，补入“道路”；包含内部道路和园区道路面，
  不进一步冒充已取得精确道路等级。
  原始接口空值仍保留，补充结果为 `resolvedFeatureType: ROAD`、
  `classificationSource: verified-road-surface`，预览、筛选和导出使用同一分类。
  其余空类型或 `UNCLASSIFIED` 仍显示未分类，其他明确类型优先使用官方结果。
  查询分批进行并按矢量版本缓存；失败或取消时保留上次预览。
  这是内部查询接口，不能据当前可用性保证后续永远无需认证。
- 建筑 `heightRaw` 已与官方 ASM 挤出网格 Z 分量逐项对照；
  米制含义及完整渲染变换尚未确认，不生成 `heightMeters`。
- 点锚点保留可用的名称、GUID、排序字段及原始样式号；不复刻文字图集、
  图标、道路文字、避让、箭头、室内和附加新类型。
- 未解析的图层显示编号、排序和块数量；原始响应仍保留在本地缓存。
  格式错误、越界、未知协议版本明确报错，不以空图假装成功。
- 本阶段不做跨瓦片实体合并、去重或范围裁切；统计包含完整瓦片和边缘数据。
- 官方 SDK、原始响应、前端依赖及验证产物只保存在 `tmp/`；
  服务只监听 `127.0.0.1`，上游地址固定，不支持任意 URL 转发。
  页面样式复用相邻腾讯验证页，依赖继续使用 Leaflet 1.9.4 和 Lucide 0.468.0。

## 本轮验证

2026-10-23，矢量 v088，更新标记 20261021：

- 北京、济南、上海、广州各检查原生 z12、z15、z17、z19，共 16 组，
  36,320 个已解析要素。
- 194,378 个顶点与官方 SDK 的双精度差分还原一致；
  同时逐项核对官方 ASM 的 Float32 累加结果。
- 692 栋建筑的高度原值与官方 ASM 挤出网格 Z 分量一致。
- 北京九瓦片包含 4,496 个已解析要素，其中建筑 1,040 个。
  1440×900 和 390×844 下核对实际底图、Canvas 像素、筛选、要素点击和主动导出；
  没有页面脚本错误和横向溢出。
- 同一批四城 16 组样本共 374 个不同原始样式编号，官方接口返回 323 个非空分类。
  其中非点要素有 33,209 个明确业务分类，1,298 个为空类型或 `UNCLASSIFIED`。
  已覆盖 1,345 个水体、264 个绿地、692 栋建筑、443 个铁路/高铁及 117 个地铁要素；
  分类来自官方字符串映射，不依据颜色推测。
- 内部道路回归：北京九瓦片的 `504812/504813` 共 330 个道路面从未分类移入道路；
  该批道路计数从 499 变为 829。用户指出的环路 93 个三角面的中心均贴近原生 z17
  官方 `LOCAL`（60499）道路中心线，百度墨卡托平均距离约 1.07、最大约 3.20。
  补充规则只识别道路大类，不从邻近中心线推断每个面的具体道路等级。
  运行 `node --test tools/baidu-gis-prototype/classification.test.mjs`
  核对漏分类、版本及几何限制、官方结果优先和 JSONP 校验。

本机脚本、报告和截图在 `tmp/baidu-gis-research/`，
服务缓存位于 `tmp/baidu-gis-prototype/`。
