# 下载组件模型

预览器现在的导出页把一次任务拆成三套互相牵制的全局开关：卫星图来源、GIS 图层加组合方式、导出类型。输出参数又是全任务共用的。结果是勾选「合并大图」会作用到每一个已选图源，建筑 FBX 还必须连带勾上底板 FBX，命令行里已经有的形态、原始瓦片、高德地图类型也挂不进去。

这次只重排导出配置的信息结构，不改瓦片数学、缓存格式和下载器。输出内容变成组件，
图源和高程变成组件上的参数。界面固定使用一个默认内容区，不提供新增内容组；内部组
对象仅用于兼容输出目录和任务记录。

## 用户操作

下载卫星图时，不再先勾一排图源再勾一排输出类型。

1. 任务只保留范围：中心、半径、层级、输出目录。
2. 使用自动创建的「当前预览」内容区。名称会变成输出子目录，组前的勾选决定是否执行。
3. 在组里添加组件。组件就是最终要落盘的东西：大图、标准 XYZ、原始瓦片、底板模型、建筑模型、GeoJSON。
4. 给组件挂参数。图源和高程都是参数。影像和每一种 GIS 图层都是图源，用同一种行，不再分成两块。

同一个内容区可以同时包含这些组件：

- 大图挂高德卫星、百度卫星，再挂道路和水。导出时道路和水合并进每一张卫星大图。
- 标准 XYZ 只挂高德卫星。
- 底板模型挂高德卫星，形态为平面，并打开高程。
- GeoJSON 挂道路、水、建筑。
- 建筑模型的几何来源是 GIS 建筑，屋顶模式为卫星图，并引用底板模型。

## 四个对象

任务负责排队和共用范围。默认内容区负责输出子目录，组件负责一种输出，参数负责这个
组件从哪取数、写成什么样。内部仍保留组对象，但界面不允许创建多个组。

同一任务里，相同图源和高程只下载一次。图源身份就是「高德卫星」或「道路」这种完整条目，不再是图商再加上一个地图类型下拉。组件只消费这次下载的结果，避免一组里的大图和底板模型各下一遍。

组件之间的依赖要写在参数里，不再靠“同时勾选了什么”来猜测。建筑屋顶使用卫星图时，必须引用本任务中的一个底板模型；那个底板模型要带卫星贴图，并先于建筑模型生成。

## 组件

| 组件 | 现在落在哪 | 参数 |
| --- | --- | --- |
| 大图 | `exportMergedImage`，以及把 GIS 合并进影像或单独导出的大图 | 一份图源列表、格式、最大边。列表里可以同时有影像和 GIS |
| 标准 XYZ | 预览里的「XYZ 切片」，命令行金字塔。标准 Web Mercator，不是图商原始瓦片 | 与大图相同的图源列表和合并规则；分辨率可选 256、512、1024 |
| 原始瓦片 | 命令行 `--output-mode raw`。预览导出目前没有这项 | 只接受影像图源，导出图商原始瓦片 |
| 底板模型 | 「FBX 切片与网格」。卫星或 GIS 贴到地形网格上，不是建筑 | 贴图图源、贴图尺寸和格式、形态、细分、高程、贴图降级 |
| 建筑模型 | 「建筑 FBX」整块，含墙体、屋顶和 `buildings.fbx` | GIS 建筑、墙体、屋顶、楼层和材质参数、可选高程。卫星屋顶引用底板模型 |
| GeoJSON | `exportGeoJson` | GIS 图层、标注和基础图层、分类覆盖 |

## 大图怎么合并

大图只有一份图源列表。不另设 GIS 区，也没有「添加 GIS 图源」，更没有合成方式下拉。点「添加图源」时，影像和 GIS 出现在同一个列表里，选中后都用同一种行：名称在左，移除在右。

影像图源各自成张：

- 高德卫星、高德电子、高德路网。这三项对应现在的 `--map-type`，但是三个独立图源。高德后面不再挂「卫星 / 电子地图」下拉。
- 百度卫星、腾讯卫星、天地图影像、天地图多时相、Google 卫星、Bing 卫星、ArcGIS 影像。

GIS 图源一层一条，当前来自高德 Web 矢量：道路、建筑、水、点、绿地、边界、高速、地铁、其他。

把 GIS 放进大图，就是要合并进这张大图一起导出：

- 选了影像，也选了 GIS：每张影像大图都叠上这些 GIS 图层。
- 只选了 GIS，没选影像：只导出合并后的 GIS 大图，不要求再选卫星图。
- 只选了影像：只导出影像大图。

道路和水要各出一张图时，做成两个大图组件，每个只挂一个 GIS 图源。现在的「叠加到所选卫星图 / 图层合并 / 图层单独输出」三个开关取消。标准 XYZ 使用同一套图源和同一条规则。原始瓦片只接受影像图源。

## 参数

图源是同一种参数。GIS 行可以带自己的颜色，初始值来自预览页调色板，就在这一行里改。除此之外不给影像和 GIS 做两套控件。

影像图源还可以带这些附加项：天地图多时相的年份、区域、时间线 Key。历史年份沿用当前登录 Cookie，Cookie 不写入任务记录。可选缓存目录、代理或直连。Google 默认代理留在对应图源上。

GIS 图源的基础图层、标注图层、忽略显示层级、线宽、点半径、瓦片边长、Web API Key 和版本放在高级区，默认不动。这些能力现在在 `AmapVectorRenderOptions` 和命令行里。

「建筑按高度着色」不进入新的导出界面。它现在对导出没有实际用处，大图和 GIS 参数里都不放这个勾选。

高程：

- Copernicus DEM GLO-30，缓存仍是 `cache/Copernicus高程`。
- 采样间距，默认 30 米。
- 零面仍取本次范围的最低高程。
- 只出现在底板模型和建筑模型上。打开后，底板写出带高差的网格和 `高度/meta.json`。

组件引用：

- 建筑模型的卫星屋顶指向一个底板模型。
- 被引用的底板模型必须包含卫星贴图，并且任务会先生成它的 FBX 清单。

## 现有字段怎么搬

`ExportConfiguration` 里现在的全局字段拆开之后是：

| 现有字段 | 新位置 |
| --- | --- |
| `centerWgs84`、`radiusMeters`、`zoom` | 任务范围 |
| `outputRoot` | 任务输出目录 |
| `satelliteSources`，含多时相年份、Key、区域、Cookie | 组件上的影像图源。高德电子、高德路网也在这里，不再用地图类型字段。Cookie 继续只活在进程内 |
| `gisCategories`、`gisColors` | 图源列表里的 GIS 条目，颜色跟在对应条目上 |
| `colorBuildingsByHeight` | 不进入新界面 |
| `gisModes` | 取消。大图有影像图源时把 GIS 合并进去；只有 GIS 图源时只导出 GIS |
| `exportTiles` | 有没有标准 XYZ 组件 |
| `exportMergedImage`、`mergedImageFormat`、`mergedImageResolution` | 大图组件 |
| `exportFbx`、`fbxTextureSize`、`fbxTextureFormat`、`fbxTerrainSampleRateMeters` | 底板模型。它不再代表建筑 |
| `exportTerrainHeight` | 底板或建筑上的高程参数 |
| `exportGeoJson` | GeoJSON 组件 |
| `exportBuildingFbx` 和全部 `building*` | 建筑模型 |
| `ExportGisUiGroup` | 取消。图层集合放到 GIS 参数里，组只表示交付分组 |

命令行有、预览导出还盖不住的部分：

| 现有能力 | 新位置 |
| --- | --- |
| `--output-mode raw` | 原始瓦片组件 |
| `--output-mode pyramid` / `both` | 标准 XYZ，可与大图同时存在 |
| `--map-type` | 拆成高德卫星、高德电子、高德路网三个图源，没有类型下拉 |
| `--fbx-shape plane/sphere/both` | 底板模型的形态。预览里的 FBX 现在始终是平面 |
| `--fbx-subdivision` | 底板模型。没开高程时用于球面网格，默认 64 |
| `FbxTextureDistanceOffsets` | 底板模型高级参数。按距中心的距离降低贴图级别 |
| `--cache`、`--proxy`、`--no-proxy` | 对应卫星图源 |
| `--concurrency` | 任务级，0 仍表示按硬件线程数 |
| `includeBaseLayers`、`includeLabels` | GIS 参数 |
| `ignoreFeatureZoomRange`、线宽、点半径 | GIS 高级参数 |
| `textureUnitLayer`、`textureUnitPixelSize` | 建筑模型高级参数，默认 5 层和 64 像素 |

文档里写过「右键把 GIS 分类合并成组」。当前界面实际是每个分类一个勾选，再加三个全局组合方式，`exportGisGroups_` 也是一分类一组，没有合并手势。这项改为每个 GIS 图层一个图源。要合并，就把它们挂进同一个大图组件。

## 校验

这些现有报错改成组件自己的条件，不再要求用户先勾上另一类输出：

- 范围：经纬度合法，半径大于 0，层级 1 到 30。
- 至少有一个已勾选的组，且其中至少有一个组件。
- 大图和标准 XYZ 至少有一个图源。只有 GIS 图源时允许导出，不要求再选卫星图。
- 大图同时有影像和 GIS 时，每个影像结果都合并这些 GIS 图层。
- 建筑模型的 GIS 参数必须包含建筑。不再要求同时勾选底板 FBX。
- 屋顶模式为卫星图时，必须引用一个带卫星贴图的底板模型。
- 高程不能单独成为输出。
- 图源没有地图类型下拉。高德电子和高德路网只能作为独立图源添加。
- 天地图历史时相仍要求已刷新的时间线、区域和当前登录态；最新影像不需要 Cookie。
- JPG 可以选，但 GIS 透明结果会丢失透明通道，参数上给出说明。

## 执行顺序

队列、取消、记录文件和任务页保持现在的串行任务。一个任务内部改成：

1. 收集已勾选组里的全部组件，检查引用。
2. 按参数身份合并下载：卫星瓦片、GIS PBF、Copernicus 分幅。PBF 仍是唯一跨运行复用的 GIS 原始数据。
3. 先生成被引用的底板模型，再生成建筑模型。其余组件按组的顺序、组内组件的顺序输出。
4. 卫星屋顶的 `buildings.fbx` 继续写进被引用底板的 FBX 目录，复用那里的贴图清单。组件自己的目录记录这个路径。

建议的目录：

```text
<输出目录>/导出任务/<任务ID>/
├─ 卫星底图/
│  ├─ 大图/高德卫星.png
│  ├─ 大图/百度卫星.png
│  ├─ XYZ/高德卫星/
│  └─ 底板模型/高德卫星/FBX/
├─ 规划 GIS/
│  ├─ 大图/道路+水.png
│  └─ GeoJSON/数据.geojson
└─ 建筑/
   └─ 建筑模型/
```

原始瓦片缓存继续按图商放在 `cache/` 下，不跟任务目录混用。换输出目录仍然不搬缓存。

## 导出页

导出仍从预览工具栏进入，任务页不动。配置页不再纵向堆「导出内容、导出类型、输出参数、建筑 FBX」四块。

页头保留标题、范围摘要、导出任务和返回。范围收成一条：经度、纬度、半径、层级、输出目录。

下面是默认内容区。内容区有勾选、名称、组件行和「添加组件」，不提供「添加内容组」。
组件行只显示名称、参数摘要、参数和移除。点参数打开右侧参数板，范围和组件列表留在原地。

添加组件的菜单固定为六项：大图、标准 XYZ、原始瓦片、底板模型、建筑模型、GeoJSON。大图参数板只有图源和输出两项。添加图源同时列出影像和单个 GIS 图层，不另设添加 GIS，也不放建筑按高度着色。

从预览打开导出时，用当前地图和当前 GIS 预填一个名为「当前预览」的组：有底图就放一个大图组件，并把当前影像做成一个图源；开了 GIS 就把每个图层再做成一个图源挂到这个大图上。不自动添加模型。用户可以删掉这组。

空内容区显示添加组件。
