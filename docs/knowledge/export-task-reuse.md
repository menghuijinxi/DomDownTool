# 导出任务内修改参数与重命名

## 需求与影响

三维软件经常按固定路径导入 FBX、贴图和地形。修改分辨率、范围或网格参数时，
如果创建新的任务 ID，就会产生另一套输出目录，难以反复更新场景。
任务列表因此区分“修改参数并重新下载”和“复制参数新建任务”。

## 任务身份与保存

`ExportTaskManager::Restart` 只接受已经结束的任务，复用 ID、创建时间和
输出目录，更新配置与任务详情并重新排队。输出位置以原记录为准，不接受配置中的
新目录；界面也禁用输出目录编辑。失败和取消任务的“继续任务”使用同一入口。
运行中或排队中的任务需要先取消，才能修改参数。

导出配置页页头的任务名称始终可编辑。新建时默认留空并自动命名，复制和修改时带入
原任务名称；名称草稿在往返地图范围编辑时保留，取消则不保存。
`Enqueue` 在创建记录前校验名称，`Restart` 在同一次任务状态更新中保存名称与参数；
不传名称的“继续任务”保留当前名称，避免重试时恢复成旧的自动名称。

原有参数图标及位置仍用于复制配置；新增的铅笔图标用于修改原任务。不能把原有参数图标
挪给新行为，再给复制入口换图标，否则用户会把两个入口认反。
通过新增入口进入后，配置页右下角的提交按钮显示“重新下载”；通过复制入口进入后，
仍显示“加入导出队列”。从配置进入地图编辑范围后，通过工具栏返回配置必须保留
原任务 ID；该入口不能按普通新建导出清除编辑状态。
两个入口带有实际渲染的悬停说明，分别提示“复制参数新建任务”和
“修改参数并重新下载此任务”。当前 SkiaUI 不会自动把 HTML `title` 渲染成提示，
因此使用按钮内的提示元素与 `:hover` 样式，避免只有属性却看不到说明。
任务列表其余操作、页头按钮及确认弹窗统一复用这一提示样式；“移除记录”明确保留文件，
“永久删除”明确删除任务记录和导出文件。任务名称旁的提示从按钮左侧展开，避免短名称时
提示框越过窗口左边缘。
任务页页头和任务名称所在列需要独立的显示层级，避免提示被统计栏或进度信息覆盖；
悬停测试同时检查提示的可见面积，防止只露出边缘也被误判为显示正常。

`Rename` 只更新任务显示名称，避免改变已被三维软件引用的目录和文件名。
名称去除两端空白，拒绝空名称、控制字符和超过 512 字节的内容。
名称与修改后的配置沿用现有任务 JSON 保存格式，重启后恢复。
重命名弹窗独立于任务列表，进度刷新不会重建正在输入的文本框。

## 输出替换

直接向原目录写入会混合新旧瓦块，缩小范围或切换输出格式时尤其明显。
重新下载先在任务目录旁创建唯一的暂存目录，复用现有数据缓存；
全部生成并写好转换记录后，先将原目录移到备份，再将暂存目录移到原位置。
替换失败时恢复原目录；失败或取消的下载清理暂存目录并保留旧结果。
最后更新目录的短暂阶段不接受取消，防止已发布新结果却显示为已取消。

分组导出必须遵循执行目录覆盖值；建筑组件的 `引用.json` 则必须记录最终目录，
不能保存暂存位置。FBX 材质、Cesium 内容等已有相对引用可随目录一起移动。

该方案需要同时容纳新旧两份结果的临时磁盘空间。文件被其他程序占用时，
目录替换可能失败，任务会提示关闭占用程序后重试。原目录恢复也失败时，
错误中保留备份位置，避免丢失旧结果。进程被强制结束可能留下唯一命名的
暂存或备份目录，不自动删除无法确认归属的历史文件。

## 验证与排查

`ExportTaskManagerTest` 验证创建时自定义名称、非法名称校验、重新下载时保存名称、
同 ID、同路径重新下载、配置持久化、
旧产物清理、失败及运行中和排队中取消时保留原文件，以及 Windows 目录被占用。
`PreviewRangeEditorTest` 使用生产 HTML 与控制器验证重命名、空名称提示、
真实窗口异步切页、两个入口各自的提交文案、悬停提示实际显示和移出隐藏、
修改半径、保留中心精度、取消返回任务、创建时命名及留空自动命名、
名称草稿往返范围编辑后保留、
编辑范围返回后仍更新原任务和复制参数新建任务，
并生成桌面及窄窗口截图。

遇到路径变化先检查调用方是否仍用 `Enqueue`，再检查执行目录覆盖是否被清除。
遇到旧瓦块残留先确认替换是否成功，遇到引用失效检查清单是否含 `.rebuild-`。
任务失败时区分生成失败和目录占用；保留的原文件不会代表新参数已生效。
