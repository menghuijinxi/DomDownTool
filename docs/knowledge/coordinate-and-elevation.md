# 模型坐标与高程基准

## 不同范围任务的模型高度错层

### 现象与影响

相同中心先导出内圈高精度地形，再扩大范围导出外围低精度地形时，
即使使用相同 DEM，模型也可能整体上下错位。地形、带高程建筑、
旧版平铺导出和分组组件导出均受影响；负海拔还可能被截平。

### 根因与定位

水平坐标已经使用中心经纬度定位，但预览任务为 FBX 指定了当前范围最低高程作为高度基准。
范围扩大后最低点可能变化，导致相同地理点的局部 Z 不同。
地形采样和建筑基础采样又使用 `max(0, elevation - reference)`，把负值截为 0。

排查时沿 `ExportTaskManager::RunExport` 和 `RunGroupedExport` 查找
`SetFbxElevationReferenceMeters`、`ApplyBuildingFbxElevation`，
再追踪 `DownToolBase` 地形高度场及 `SampleBuildingTerrainHeightRange`。
同时检查 `高度/meta.json` 的 `referenceMode` 和 `referenceElevationMeters`，
不能只看水平中心是否一致。

### 修正与兼容

- 预览 FBX 固定使用海拔 0，模型原点由中心经纬度与海拔 0 决定。
- DEM 使用原有 EGM2008 海拔，地形和跟随地形的建筑保留有符号高程。
- 元数据写出 `referenceMode: sea-level`、`referenceElevationMeters: 0`，
  `verticalDatum` 仍为 `EGM2008`。
- 球面模型继续在同一中心的零高程曲面上叠加高程，保持既有曲率处理。
- 底层显式指定参考高程的 API 保留，允许调用方自行指定偏移；预览任务不再自动取最低值。
- Cesium 继续使用已有的高程偏移和大地水准面转换配置；不能把 EGM2008 海拔与
  WGS84 椭球高混为一谈。
- 已导出的模型不会自动改写。旧模型若元数据为 `referenceMode: minimum`，
  应重新导出后再与新模型拼接。

统一原点解决的是整体坐标偏移。不同层级的 DEM 采样间距、网格简化误差仍可能造成
接缝处的局部高度差，不能据此认为低精度与高精度网格的边界顶点必然重合。

### 验证与复查

`ExportTaskManagerTest` 使用离线 DEM，分别验证 20 公里 / z18 与 40 公里 / z15。
两种范围的最低高程分别为 150 米和 25 米，旧式任务与分组任务仍须输出相同的 0 米基准。
测试缓存隔离在 `tmp` 内，不使用真实缓存或在线数据。

`PostProcessFbxTest` 与 `AmapBuildingChunkTest` 对平面和球面分别检查
0、150、-35.5 米高程，验证顶点相对零高程模型的高度偏移。
三个测试均先在旧实现上失败，再验证修复通过。

再次遇到多任务错位时，依次检查中心、模型形态、高程基准、垂直基准、
旧产物元数据，最后检查边界采样与简化误差。

## 独立底板预览只显示一条窄带

### 现象与影响

启用“每块单独导出 FBX”后，任务包含数百个文件，预览却只显示一条窄带，
容易被误认为各块坐标丢失。所有超过 32 个 FBX 的任务预览均受影响。

### 根因与排查

`PreviewController::findTaskFbxFiles` 在遍历目录时以 `files.size() < 32` 提前结束，
只把前 32 个文件交给渲染器。文件枚举顺序使这些块可能集中在一列，
相机又按已加载网格的包围盒取景，因此呈现狭长形状。

实际案例导出了 529 个 FBX；原预览的 15,558 个顶点、27,184 个三角面
与前 32 个文件的 Assimp 读取结果完全一致。前 32 块水平范围约 2.15×39.9 公里，
全部文件范围约 40.16×39.92 公里，共 274,036 个顶点、484,001 个三角面。
读取时累计根节点和子节点变换，检查的是场景坐标，不只看网格局部坐标。

### 修复与验证

删除文件枚举数量上限，保留跨文件统一包围盒、坐标变换及后台网格和贴图加载流程。
已有文件可以直接重新打开预览，无需重新导出。

`PreviewRangeEditorTest` 离线生成 49 个独立底板，通过任务页真实预览按钮加载，
检查总 DrawCall 和总三角面数覆盖所有文件。测试在修复前连续两次只加载 32 块。
`PostProcessFbxTest` 继续检查拆分和合并输出的顶点、节点变换、法线及 UV 一致。

再次遇到“缺块或错位”时，先核对实际 FBX 文件数与预览总 DrawCall，
再比较预览顶点和面数，最后检查节点累计变换与完整包围盒。
文件数限制不能静默截断模型；性能限制应保留完整空间覆盖并明确显示加载状态。

## 不重新导出时兼容旧平面坐标

### 旧任务核对

任务 `1790567037646-0` 使用 WGS84 中心 `(113.144184, 22.186737)`，
平面模型为局部 EPSG:3857。原 `高度/meta.json` 中仍保存
`referenceMode: minimum`、`referenceElevationMeters: -46.816097259521484`，
垂直基准为 EGM2008。因此旧海拔零面在模型局部 Z 为 46.8160972595 米，
不能按现版固定零海拔，也不能把最低高程误认为平均高程。

源文件 117 块，带面角属性的 3,718,326 个源顶点全部通过贴图像元范围与 UV
独立还原经纬度，EPSG:3857 水平最大差异 0.375466 厘米。
另用本机原 Copernicus 缓存抽查 286,060 个顶点，
`max(0, DEM海拔 - 参考高程) * 100` 的 Z 最大差异 0.030152 厘米。

### 兼容办法

`tools/unreal-legacy-plane/DomDownLegacyPlaneCoordinates.h/.cpp` 提供：

- `TryLongitudeLatitudeToUEXY`：只输出局部 XY 厘米坐标，不加载任何查询数据。
  Z 由调用方通过现有地面射线获取时使用此接口，命中点不要再次补偿旧高度偏移。
- `TryLongitudeLatitudeAltitudeToUE`：已知海拔时使用原点、参考高程和旧截平规则；
  返回厘米坐标，导入后东向 +X、南向 +Y。
- `LoadSurface` 和 `TryLongitudeLatitudeToUE`：只有经纬度时，使用从原 FBX
  提取的三角面，在原几何内部插值得到 Z。高度已包含旧基准偏移，不能再次补偿。
  不依赖 DEM、碰撞、物理射线或 UE 网格的运行时 CPU 副本。

旧资产不修改、不重导。查询数据仅由原顶点提取，约 42.55 MiB；
按 250 米空间格子索引三角形，没有将旧地形近似成低精度高度图。
无网格覆盖时明确返回 false，不静默回退零高度。

### 验证与边界

在 UE 5.5.4 中使用目标导入插件同一 UFbxFactory 及轴、单位、顶点变换选项，
实际导入完整旧 FBX；只跳过图片和材质处理，不保存测试资产。
导入得到 644,590 个去重顶点和 1,239,442 个三角面。
逐一检查顶点及每个三角面的两个内部点，零遗漏，与导入三角面的误差远小于毫米。
再按原 UV 独立还原每个三角面重心的经纬度，1,239,442 次查询零遗漏，
最大三维差异 0.338673 厘米，其中水平最大 0.331770 厘米、竖直最大 0.231784 厘米。
纯 XY 接口在未加载地面数据的状态下复查同一组 1,239,442 个经纬度样点，
全部转换成功，最大水平差异仍为 0.331770 厘米。

该验证针对这份旧底板的 LOD0 与统一变换下的相对位置，不替代影像和 DEM 自身的
地理精度评估。只做投影不能由经纬度推导真实地面高度；已知 DEM 高度的投影结果，
也不能代替旧三角面内部的实际高度。调用方已有地面射线时，只做 XY 投影并使用
射线命中高度即可；没有射线时才需要额外的三角面查询数据。
输入须为 WGS84；模型经过共同变换时，对结果执行同一 `TransformPosition`；
独立移动各块或修改顶点后，须面向修改后的表面取高。
本机数据、散列和验证入口记录于 `tmp/local-environment/ue-coordinate-validation.md`。
