# 测试与调试经验

## 导出任务取消必须贯穿整个流水线

### 现象

运行中的导出任务点击“取消”后界面看似没有反应，任务仍可能继续执行缓存扫描、
合并大图或 FBX 后处理，直到当前长阶段结束才显示“已取消”。

### 影响范围

卫星瓦片缓存扫描与下载、XYZ 金字塔、合并大图、FBX、GIS 下载与渲染、GIS 图像
复制与合成、GeoJSON 写出，以及任务进度 UI。

### 根因

- 任务管理器只向当前已注册的下载器设置停止标志，下载器注册前存在取消竞态。
- 多个 CPU 和文件处理长循环没有检查停止标志。
- 取消后的普通进度回调仍会覆盖“正在取消”状态。
- 原测试没有真正调用 `ExportTaskManager::Cancel()`，无法覆盖并发时序。

### 解决方案

- 下载器同时读取自身停止标志和任务管理器提供的取消回调。
- 所有长循环在领取下一项工作前检查取消，阶段边界再次检查。
- 文件复制、图像合成和 GeoJSON 写出接受同一个取消回调。
- 任务进入取消状态后忽略后续普通进度，界面禁用取消按钮并显示“正在取消”。
- 用可控下载器建立无网络回归测试，覆盖运行中、排队中和下载器注册前取消。

### 验证方式

- `ExportTaskManagerTest`：任务取消状态、最终状态和注册竞态。
- `PostProcessPyramidTest`：停止后不再领取下一张后处理瓦片。
- `AmapVectorGeoJsonTest`：取消时不创建 GeoJSON 输出。
- `AmapVectorPngTileTest` 与完整 CTest：检查 GIS 与其他导出行为没有回归。

### 快速检查清单

- 新增长阶段是否在内部循环和阶段边界都检查取消？
- 取消发生在资源注册前时，后续工作是否仍会启动？
- 取消后的进度回调是否会覆盖取消状态？
- 单次不可中断的第三方调用返回后，是否停止领取下一项工作？
- 测试是否覆盖真实并发时序，而不只是直接设置最终状态？

## SkUI 滚动区不能只靠截图缩略图判断横向裁切

### 现象

参数面板没有纵向滚动条时，输入框和下拉框的右边框被裁掉；出现纵向滚动条后，
滚动条又覆盖复选框、输入框和分段按钮。离屏截图整体看起来正常，但放大检查时同样
能看到控件右边框缺失。

### 影响范围

使用 `overflow-y: auto` 的窄侧栏、弹窗和其他固定宽度滚动容器，尤其是内部控件使用
固定宽度或不可收缩 Flex 项时。

### 根因

- `scrollbar-gutter: stable` 在当前 SkUI 布局中没有形成可依赖的内容安全区。
- 滚动条和内容使用同一块右侧区域。
- `overflow-x: hidden` 会把横向溢出直接截掉，使问题看起来像控件本身少画了一条边。
- 只检查整张缩略图，没有检查控件右边框和滚动区的横向范围。

### 解决方案

- 在滚动容器内增加独立内容层，并为内容层固定预留右侧安全距离。
- 允许输入框、下拉框和分段按钮在窄面板中收缩。
- 装饰性元素使用专用类，避免 `.row span { flex: 1 }` 一类宽泛选择器把色块等子元素拉伸。
- 分段按钮文字较长时，为按钮组设置可容纳完整文字的最小宽度，并让整个按钮组换行。
- 滚动容器中的单个 Flex 卡片不能在内容超高时继续收缩；应让卡片按内容自然增高，并用
  `min-height` 保持短内容时铺满视口，否则越界子元素不会计入父级可滚动高度。
- 保持外层只负责滚动，内层负责内容宽度，避免把滚动条避让交给单个控件。

### 验证方式

- 分别渲染无滚动条的短参数面板和有滚动条的长参数面板。
- 放大检查输入框、下拉框、复选框和按钮的完整右边界。
- 通过 `Runtime::scrollStateById()` 断言 `maxScrollX == 0`；长面板同时断言
  `maxScrollY > 0`。

### 快速检查清单

- 滚动条与最右侧控件之间是否有稳定间距？
- 无滚动条时控件右边框是否仍完整？
- 窄窗口下固定宽度控件是否允许收缩？
- 测试是否同时覆盖短内容、长内容和窄窗口？
- 是否检查了 `maxScrollX`，而不只是查看整张截图？

## SkUI 动态参数面板要同时维护事件标记和滚动状态

### 现象

动态生成的分段按钮外观正常但无法点击；勾选参数后面板重新渲染，滚动条会跳回顶部。

### 根因

- SkUI 只把带 `data-action` 的普通按钮作为业务动作节点，只有 `id` 不会产生点击回调。
- `replaceHtmlById()` 替换滚动容器本身时会创建新节点，旧节点的滚动偏移不会继承。
- 在事件回调中替换整个参数面板后立即恢复偏移仍依赖事件收尾和布局时机，不够可靠。

### 解决方案与验证

- 所有动态按钮统一由 helper 写入 `data-action`，并在离屏测试中点击按钮文字区域校验 ID。
- 同一组件的参数变化只替换滚动容器内的 `export-panel-scroll-content`，保留
  `export-panel-body` 节点；切换组件时才重建整个参数面板并从顶部开始。
- 回归测试在按钮点击回调内部替换参数内容，并在事件结束后断言外层滚动容器的
  `scrollY` 仍大于零。
