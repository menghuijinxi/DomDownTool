# 腾讯 Web 矢量瓦片

前端规则已经接入 C++。桌面端 GIS 下拉面板可选择高德或腾讯，导出组件可分别添加
两家的类别，并与 WGS84 SHP 混合使用。前端独立对照入口仍保留在
[腾讯矢量 GIS 原型](../../tools/tencent-gis-prototype/README.md)。

## 数据来源

2026-10-23 从腾讯官方 GL JS SDK 读取 `vectorSrc`、`dataVersion`、
`styleNameConfig`、坐标还原和 `getOriginalGroundFeatures` 逻辑。
实际验证的矢量数据版本为 405，样式版本为 99。

- SDK：`https://map.qq.com/api/gljs?v=1.exp`
- 样式入口：`https://vectorsdk.map.qq.com/fileupdate/jsapi/style?autoup=1&id=0&version=-1`
- 单瓦片模板：
  `https://rt{0..3}.map.gtimg.com/tile?styleid=0&z={z}&x={x}&y={tmsY}&version=405&building=1&style=100&compress=1&mapType=hybrid`

这属于 SDK 内部接口；请求和解析规则需集中在腾讯专用模块，不能当作稳定公开协议。
前端服务缓存 SDK 并保留 SHA-256，便于追溯本次规则对应的版本。

## 坐标与解码

- 腾讯矢量使用 GCJ-02 Web Mercator，局部瓦片范围为 256×256，Y 向下。
  以 XYZ 选取瓦片，请求时转为 `tmsY = 2^z - 1 - xyzY`。
  与高德矢量的专用经纬度格网不同，不能复用高德选块或 PBF 解码逻辑。
- SDK 配置最大数据层级为 18。页面将数据层级与地图显示层级分别记录，
  开启样式筛选时依据当前显示层级重新检查样式区间。
- HTTP 返回 JSON 信封。若无明文 `ret`，先标准 Base64 解码 `data`，再对字节对
  进行三轮腾讯变换，UTF-8 解码并取最后一个 `}` 之前的 JSON。
  每轮令 `(L, R) = (R, L XOR (ROL8(R,2) XOR (ROL8(R,1) AND ROL8(R,3))))`。
  只有 `ret=0` 且 `features` 为数组才视为成功。
- `compress=1` 的局部坐标首对为绝对值，后续对分别累计 X/Y 差分；
  `compress=0` 为绝对局部坐标。每条路径单独还原，坐标允许超出 0–256，
  不能截断边缘缓冲。
- 成组文字拆开保留；地点与文字显示锚点，不复刻字体图集与文字排版。
  扩展 `pois` 按独立来源保留，当前真实样本中尚未出现该字段的有效要素。
- 对未知几何组、错误响应和损坏坐标明确报错。合法但退化的原始路径保留记录，
  以 `geometry: null` 和 `geometryIssue` 标明。C++ 解码结果保留原始属性与空几何，
  范围查询不将缺少有效边界的退化记录加入绘制和导出集合，原始缓存保留完整响应。

## 分类与高度

图层高位 `id & 0xf0000` 区分点、线、面、文字与箭头，分别为
65536、131072、196608、262144、327680。
在几何组内使用 SDK 自带的分类表，保留原始 layer ID、样式名和原始字段。

| 几何组 | SDK 标签 | 业务分类 |
| --- | --- | --- |
| 面 | `building` | 建筑 |
| 面 | `water` | 水体 |
| 面 | `grass`、`park` | 绿地 |
| 面 | `subwayarea` | 地铁 |
| 线 | `highway`、`motorway` | 高速 |
| 线 | `mainroad`、`secondaryroad`、`street`、`path` | 道路 |
| 线 | `water` | 水体 |
| 线 | `subwayline` | 地铁 |
| 线 | `guojie`、`shengjie` | 边界 |
| 点 / 文字 | 任意 | 地点 / 文字 |
| 其余 | 未映射业务标签 | 其他，保留原始编号 |

不能把名称含 building 的地点当作建筑轮廓，也不能把居住区、大型场地或体育场面
一概归为建筑。样式表中的未知 ID 保留为未知样式，不能靠样本名称猜含义。

建筑图层 `196619` 的第三字段在 SDK 中乘以当前纬度处的每米像素数，
用于建筑挤出；当前验证页将这一字段记为 `heightMeters`。只有正值用于高度着色。
其他建筑图层尚未核对高度字段，线图层的数值第三字段可能表示沿线起始距离，
不能统一解释为高度。

压缩与未压缩响应的原始图层、还原坐标、字段和建筑高度全部一致。

| 样区 | z16 要素数 | z16 正建筑高度范围 |
| --- | ---: | ---: |
| 北京东城 | 683 | 4–28 m |
| 济南校准区 | 199 | 4–100 m |
| 上海陆家嘴 | 321 | 4–240 m |
| 广州珠江 | 229 | 4–160 m |

北京 z16 连续九瓦片共 6,253 个要素也全部通过对照。其中 15 个原始建筑面退化，
4,685 条建筑记录中可绘制 4,670 条；可绘制全部要素为 6,238 条。
计数包含完整瓦片与缓冲区，尚未裁剪或跨瓦片去重。

Playwright 在 1440×900 和 390×844 检查真实地图像素、底图切换、分类开关、
属性点击、层级筛选、压缩对照、主动导出、非法坐标及取消加载。
两个尺寸均无页面脚本错误、横向溢出或请求失败。

## 放大后的建筑形状

2026-10-23 用户反馈 z16 建筑放大到显示 z19 时，出现大量三角形、梯形和
相邻轮廓粘连。对九瓦片的 4,685 条建筑原始路径检查，没有发现非相邻边的
严格交叉，但存在 2 条原始路径边线接触。多个相邻建筑共享量化坐标，
不能仅凭预览中出现尖角就推断点序解码错误。

在同一北京位置、同一显示 z20 下分别加载 z16 和 z18，z18 原始响应包含
更细的坐标和更多轮廓顶点，z16 中的尖角、狭长三角形和接触明显减少。
z16 采用 256 范围的整数局部坐标，在该纬度相邻坐标约为 1.83 m；
z18 约为 0.46 m。低层级的简化与量化影响会在放大后暴露。

验证页的数据层级固定，地图缩放不会触发重新选块下载。建筑轮廓验收应选择
数据 z18 后重新加载，并以同一显示比例比较；不能把低层级放大的结果当作
最高精度源数据。压缩与未压缩对照只能验证还原一致性，不能替代轮廓精度检查。
本机对照脚本、截图和原始坐标记录在 `tmp/tencent-gis-prototype/` 的
`compare-shape-levels.mjs`、`shape-data-z16.png`、`shape-data-z18.png` 和
`shape-level-report.json`。正式导出固定使用数据 z18，显示缩放不降低导出数据精度；
桌面预览使用 `clamp(显示层级, 3, 18)`，缩放跨越数据层级时重新请求。

## C++ 接入

- `TencentVectorDecoder` 负责信封、分类和几何还原；`TencentVectorDownloader`
  负责 Mercator XYZ 选块、TMS 请求、下载和独立缓存。HTTP、JSON、Base64、
  坐标转换、空间裁切和模型生成复用 curl、nlohmann、OpenSSL 与现有后端；
  只有 SDK 特有的字节变换和坐标差分需要专用实现，无新增依赖。
- SDK 分类表编译进程序，生成器为
  `tools/tencent-gis-prototype/generate-layer-rules.mjs`；更新 SDK 或数据版本时，
  先重新运行前端验证，再更新静态规则与版本化缓存目录。
- 腾讯几何在解码时转为 WGS84，后续预览、PNG、GeoJSON、SHP、FBX 与
  3D Tiles 使用统一要素链路。独立的 `VectorDataSource` 标识参与来源筛选，
  不依赖用户 SHP 属性里可能同名的 `provider` 字段。
- 原始缓存为 `cache/腾讯地图/gis数据/vector缓存/v405-style100-compress1/z/x/y.json`。
  只缓存解码成功的完整响应；损坏缓存重新下载，错误响应不会替换为成功缓存。
  下载工作线程返回前全部结束，HTTP 传输支持取消。
  单任务超过 100000 个来源瓦片时明确提示缩小范围并分批导出，不自动降低精度。
- 多瓦片合并时去除图层、WGS84 顶点序列、名称及高度一致的重复记录。
  对不同顶点序列和不同简化轮廓不猜测实体关系。范围处理复用已有规则：
  普通线面裁切，建筑按相交关系保留完整轮廓，排除区与 SHP 使用相同逻辑。
- 任务保留旧的 `gis.*` 高德 ID，腾讯使用 `gis.tencent.*`；旧任务无需迁移。
  各来源先按自身选中类别筛选，再交给渲染和模型后端。
- 命令行兼容旧入口，例如：

  ```powershell
  AmapGisDownload.exe --source tencent --lon 116.42 --lat 39.89 --radius 200 --zoom 19 --types building --output tmp/tencent-output
  ```

## 支持边界

- 当前样本没有嵌套多路径、带洞面或有效补充 POI；不能声称已经验证这些编码。
  C++ 对多路径面明确报暂不支持，取得真实样本确认拓扑后再扩展；补充 POI
  使用已验证的基础要素格式，人工 fixture 覆盖成组文字和 POI 的保留。
- 验证页 GeoJSON 为 GCJ-02，仅用于协议核对；正式程序的腾讯输出为 WGS84。
- 地点、道路文字与箭头的完整视觉样式不在本轮复刻范围。
- WGS84 SHP 的预览、删除和主动导出保持原流程，不引入 PROJ。
